# Развёртывание и эксплуатация

## Переменные и секреты

Фронтенду нужны только `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` и `VITE_API_URL`. Последний указывает на URL Edge Function `api`.

В Edge Function `api` обязательно задайте `ALLOWED_ORIGINS` — точный список production-origin через запятую, например `https://tests.example.ru`. Не используйте `*`. `SUPABASE_SERVICE_ROLE_KEY` доступен только Edge Functions; он никогда не попадает в `.env.local` фронтенда и в CI-логи.

Для `maintenance` создайте отдельный случайный `MAINTENANCE_SECRET` (минимум 32 случайных байта). Он передаётся только в заголовке `x-maintenance-secret` при серверном cron-вызове.

## Порядок выпуска

1. Создайте production-проект Supabase, отключите публичную регистрацию преподавателей и пригласите нужных пользователей через Auth.
2. Свяжите CLI с проектом, примените миграции и разверните обе функции:

   ```bash
   npx supabase db push
   npx supabase functions deploy api
   npx supabase functions deploy maintenance
   ```

3. Добавьте secrets `ALLOWED_ORIGINS` и `MAINTENANCE_SECRET` через Dashboard Supabase или CLI. Проверьте API только с разрешённого origin.
4. Соберите интерфейс `npm run build` и разверните каталог `dist/` на статическом хостинге. Файл `public/_headers` задаёт безопасные заголовки для хостингов с форматом Cloudflare Pages. Для другого хостинга перенесите эти же заголовки в его конфигурацию.
5. Выполните ручный smoke-test: вход преподавателя, импорт/публикация, одно назначение, открытие ссылки в приватном окне, автосохранение, отправка и отчёт.

## Очистка данных

Раз в сутки запускайте Edge Function `maintenance` из защищённого scheduler/cron:

```bash
curl -X POST "https://<project-ref>.supabase.co/functions/v1/maintenance" \
  -H "x-maintenance-secret: $MAINTENANCE_SECRET"
```

Она удаляет завершённые и просроченные назначения старше индивидуального `retention_days` преподавателя; каскадно удаляются связанные попытки, ответы, результаты и телеметрия. Выполненные удаления фиксируются обезличенной записью аудита только при ручном удалении ученика. Функция не доступна из браузера и не возвращает данные учеников.

## Наблюдаемость и резервное копирование

- Просматривайте логи Edge Functions и ошибки запуска по крайней мере после каждого релиза.
- Настройте резервные копии согласно тарифу Supabase до реальной эксплуатации.
- Уведомления должны содержать только идентификатор операции и код ошибки, без токенов назначений, ответов или персональных данных.
