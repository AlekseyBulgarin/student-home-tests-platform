# Дополнение к модели угроз: операционная панель

| Угроза | Контроль |
| --- | --- |
| Преподаватель подменяет UUID чужой попытки | JWT проверяется Edge Function, а RPC повторно фильтрует строку по `assignments.teacher_id` под блокировкой. |
| Браузер подменяет баллы, причину или шкалу снимка | DTO не принимает баллы/причину завершения; балл и `teacher`/`deadline` формируются сервером. Пороги проверяются Zod и DB constraint. |
| Случайное опасное действие в UI | Продление, пакетное продление, force finish и regrade требуют явного подтверждения. Сервер всё равно остаётся конечной точкой авторизации. |
| Ретроспективная подмена итогов сменой шкалы | У каждой завершённой попытки есть `grade_scale_snapshot`; шкала изменяется только для будущих результатов. Regrade — отдельная аудируемая команда. |
| Утечка ключей/ответов через операционный список или CSV | Панель получает только агрегаты и счётчики; CSV не включает ответы, ключи, объяснения и токены. |
| CSV formula injection | Значения, начинающиеся с `=`, `+`, `-` или `@`, получают текстовый префикс до формирования CSV. |
| Телеметрия используется как автоматическое обвинение | В UI и API это отдельный счётчик/журнал без влияния на академический балл; интерпретация и санкции не автоматизируются. |
| Аудит раскрывает PII | В audit metadata разрешены только тип действия, UUID сущности, длительность продления и агрегированные счётчики. |

Остальные угрозы — секретные ссылки, публикация ключей, идемпотентность, deadline и доступ ученика — остаются покрытыми базовой [моделью доступа](access-control.md).
