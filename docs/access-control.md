# Модель доступа и безопасность

## Матрица доступа

| Объект/операция | Преподаватель-владелец | Другой преподаватель | Ученик по attempt-сессии | Анонимный клиент |
|---|---:|---:|---:|---:|
| Ученики, тесты, назначения | чтение/изменение своих | нет | нет | нет |
| Опубликованный тест | чтение, без изменения | нет | безопасная проекция | нет |
| Закрытые ключи | через серверный отчёт | нет | только после раскрытия | нет |
| Попытка и ответы | чтение своих назначений | нет | своя попытка, пока разрешено | нет |
| Итоговый отчёт | свои назначения | нет | свой, по политике раскрытия | нет |
| Журнал событий | свой, отдельно от оценки | нет | только запись разрешённых событий | нет |

## RLS

- `teacher_profiles`: `id = auth.uid()`;
- все преподавательские сущности: `teacher_id = auth.uid()` либо проверенная связь через родителя;
- published-данные нельзя менять даже владельцу: проверка статуса в policy и защитный триггер;
- `anon` не получает прямой доступ к доменным таблицам;
- `authenticated` не получает доступ к чужим данным;
- закрытая схема `private` не выдана клиентским ролям;
- server functions вызывают минимальные RPC, а не строят запросы по присланному владельцу.

RLS считается вторым уровнем защиты. Каждая Edge Function также проверяет владельца или attempt-сессию и область операции.

## Ученическая attempt-сессия

Полный assignment-токен используется только для обмена на короткоживущую сессию. Сессия подписана серверным секретом или хранится как случайный opaque token с хешем в БД; содержит/связывает только `assignment_id`, `attempt_id`, expiry и scope. Cookie предпочтительно `HttpOnly`, `Secure`, `SameSite=Strict`; если кросс-доменная конфигурация это исключает, токен хранится только в памяти вкладки и восстанавливается через исходный секрет после перезагрузки.

Доступ всегда вычисляется из сессии на сервере. Идентификаторы из тела запроса используются только как объект действия после проверки принадлежности.

## Политика раскрытия

Серверная функция `can_reveal_results` проверяет:

- попытка отправлена или истекла;
- политика назначения;
- для `after_deadline` наступил серверный дедлайн;
- для `teacher_released` установлен `released_at`.

До этого момента ответы API не содержат правильные варианты, объяснения и производные признаки, позволяющие восстановить ключ.

## Идемпотентность и конкуренция

- начало: уникальное ограничение и `INSERT ... ON CONFLICT` возвращают существующую попытку;
- сохранение: `client_revision > last_client_revision` под row lock;
- отправка: row lock + idempotency key + неизменяемый result snapshot;
- истечение: сервер в любой операции переводит просроченную попытку в `expired`; отдельная фоновая задача улучшает своевременность, но не является условием корректности;
- две вкладки: более новая ревизия побеждает, UI получает конфликт и перечитывает состояние.

## Журнал событий

Сервер принимает только перечисленные типы, ограниченный payload и разумное окно клиентского времени. `(attempt_id, event_id)` дедуплицирует повторы; sequence помогает найти пропуски, но не считается доказательством порядка. В отчёте соседние `blur/hidden/fullscreen_exit` группируются в один понятный интервал. События не меняют балл и не превращаются в «процент честности».

## Логи и секреты

- токены маскируются до логирования; URL и тела sensitive endpoints не логируются;
- service role и signing secrets — только в server environment;
- Sentry/аналитика отсутствуют по умолчанию;
- ответы и импортируемый контент не записываются в инфраструктурные логи;
- CORS ограничивается настраиваемым списком frontend origins;
- error responses используют безопасные коды без stack trace.

## Проверки безопасности

Будут автоматизированы тесты:

1. анонимный пользователь не читает кабинет;
2. преподаватель A не читает данные преподавателя B;
3. сессия ученика A не читает попытку B;
4. активный API не содержит ключи и объяснения;
5. отозванный/истёкший токен не создаёт попытку;
6. дедлайн отклоняет сохранение и отправку;
7. повторные start/submit безопасны;
8. опубликованная версия не изменяется;
9. токены отсутствуют в логируемых полях.
